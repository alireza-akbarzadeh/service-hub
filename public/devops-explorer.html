Queries, filters & calculation rules
All work item queries and details use a shared snapshot. Iteration dates are supplied by the classification API and may be unset. Histories use each item's snapshot revision and timestamp. Creation → Merge Pending and Creation → last TestPassed are unavailable when the event never occurred. Wait for merge sums only adjacent Merge Pending → TestEnv transitions. Wait for test sums only adjacent TestEnv → TestPassed or QCRejected transitions, ignoring field-only edits. Develope time sums adjacent (InProgress or QcRejected) → (Merge Pending or TestEnv) intervals and includes every qualifying cycle; other destinations and open InProgress / QcRejected intervals are excluded. Each contributing cycle is retained in the JSON timing evidence. It does not depend on whether TestPassed has occurred. Missing or incomplete history makes metrics unavailable. No inferred QCRejectedCount is substituted for the configured field.

Connection help, API behavior & documentation


Start here
The supplied address is split into collection https://hig-devops.gig.services/HIT/ and project Hastim. The server version and permissions have not been detected. Start with API 7.0; use 6.0 for Server 2020 or 5.0 for Server 2019. Choose 7.1 only if your server supports it. Changing a project requires disconnecting and reconnecting; discovered project names appear as input suggestions.


Browser credentials and PATs
Browser mode uses credentials: 'include'; the browser decides whether cookies or integrated Windows credentials can be sent. An existing sign-in alone does not guarantee API access. Browser policy, trusted-site configuration, cookie SameSite rules, third-party cookie restrictions, and server authentication all apply. The page cannot force an NTLM/Kerberos sign-in.
PAT mode sends Authorization: Basic base64(':' + PAT) with credentials: 'omit'. The active PAT input is cleared on connect. Enabling Include PAT stores the PAT automatically as readable text in your chosen local or session storage. When Include PAT is unchecked, newly entered PATs remain in memory. Other scripts on the same origin and people with access to this browser profile may be able to read a stored PAT. No PAT is included in query/history exports or placed in cookies or URLs. Choose only the read scopes needed: Work Items (Read), Project and Team (Read), and Graph (Read) where available. Your server must allow PAT authentication. Disconnect clears the active credential reference and loaded results. Your explicitly saved PAT remains available for reconnecting; Forget saved PAT removes it from both storage locations. Erase all saved data removes this explorer's settings, PAT, and named queries from both locations and disconnects. Browser sign-in and PAT validity are managed by the server.


Automatic settings and optional query saves
Connection URLs, API versions, authentication mode, timeout, selected detail fields, result cap, and rows per table page are saved automatically when changed. Include PAT controls whether the token is included in automatic saves. The saved PAT is bound to the exact collection and Graph base URLs; editing either requires entering a PAT again or loading the matching saved settings. Connection edits are saved after a short typing pause, on a completed change, and before connecting or leaving the page. Temporarily invalid settings leave the last valid save intact and display a message. Custom query text and names are saved only through Save current query. Restored settings do not connect automatically. The browser and tab storage locations have separate named-query libraries. Changing the save location moves the connection record automatically; query libraries remain in their selected locations.
Save current query stores the name, text, query mode, fields, cap, and source-project label. The same name replaces the previous entry. Load query fills the editor and does not change the active connection or run requests. Storage is specific to this browser profile and origin. Behavior for file:// URLs varies by browser; moving the HTML file, changing browsers, clearing site data, or private browsing may make saved data unavailable. Storage failures are shown explicitly. The app writes only its own two versioned keys and does not erase unrelated site data.
CORS cannot be solved by this HTML file
Opening a file directly generally sends an opaque / null origin. A localhost server is still a different origin from DevOps. Host this file on the same HTTPS origin through an administrator-approved static path, or have an administrator configure CORS / a trusted same-origin reverse proxy. Do not disable browser security.
  • Credentialed cross-origin requests require an explicit allowed origin and Access-Control-Allow-Credentials: true; a wildcard origin is insufficient.
  • The server must handle OPTIONS preflight and allow GET, POST, and requested headers including Content-Type and Authorization when used. PAT authentication does not bypass CORS.
  • Expose X-MS-ContinuationToken (and optionally Retry-After) with Access-Control-Expose-Headers so the app can read paging and throttling metadata.
  • Network errors may mean CORS, VPN/DNS, TLS trust, blocked redirects, or browser authentication. JavaScript cannot reliably distinguish them. Check the browser Network panel. A 200 HTML sign-in page is not an API success. Redirects are rejected to keep credentials on the configured endpoints.


Discovery, paging, and completeness
Discovery loads projects and project metadata independently, so denied collection listing does not prevent project access. Projects, teams, and members use pages of 100 with a 100-page safety limit. Partial discoveries are labeled and can be refreshed. Graph fetches one page at a time using its opaque continuation header. If that header is absent on a cross-origin response, completeness cannot be verified. An optional manual token can be entered through Load next API page; obtain it from trusted server diagnostics.
WIQL supports a result cap but no generic skip / continuation API. Table Next / Previous pages through loaded rows only. If the cap is reached, narrow your query or use the ID-cursor sample with [System.Id] > LAST_ID and ascending IDs. The service also imposes query limits. Details are loaded in batches of up to 200 and use the WIQL response's asOf snapshot. Missing IDs are explicitly reported. Link queries retain source / target relationships in WIQL metadata. The table flattens the unique referenced work items; it does not imply a hierarchy.
Batch details request the selected fields plus WIQL result columns. Inspect → Load all fields & relations fetches the full work item at the query snapshot. Descriptions containing HTML are deliberately shown as text. History reads update pages for an individual work item and shows the initial state, state transitions, changed-by identities, UTC timestamps, reasons, field value differences, and relation changes. Switch to All changes to see assignment and other edits. Expand each entry to inspect field differences. History loads independently of the query snapshot and includes the latest available updates. If loading fails or is canceled, loaded entries remain visible and Load remaining history retries from the last successful page. History JSON export includes raw updates, state entries, and a completeness flag. Separate comments, attachment content, and full revision snapshots are not downloaded.


Users are not a universal server table
Graph users are documented for Azure DevOps Services at https://vssps.dev.azure.com/{organization}/_apis/graph/users, API 7.1-preview.1. The default probes the configured server collection, which may return 404 / unsupported. Use Teams → members as a server-friendly alternative. Team members cover only those teams and can include group identities; they are not a complete organization user directory. A 401 / 403 means authentication / permission trouble, not proof that the API is unsupported.


Report APIs and timing rules
Standalone bugs mode queries every Bug assigned to the selected user in the selected iterations, without requiring a linked PBI or Owner Front match. All BugTypes are included by default; the existing Develop Issue / empty filter is optional. The same snapshot, cursor paging, detail batching, history calculations, cancellation, and safety limits apply. Every field returned in the work item fields object is retained in the JSON export, included as a dynamic CSV column, and available in an expandable searchable All fields view. Unset fields may be omitted by Azure DevOps. Delivery mode also includes each linked bug’s full fields in exports and its All fields inspector.
Delivery report loads the project iteration classification tree, including startDate and finishDate, and uses Graph users or accessible team memberships. Generated WIQL filters parent types, iteration paths, and Assigned To / Owner Front; linked bugs must satisfy their own user, iteration, and BugType filters. Only direct links in the configured collection are followed. Work item details and queries share one snapshot. State updates are limited to that snapshot revision and timestamp. Duration calculations use elapsed calendar milliseconds; CSV expresses them as hours. Open waits are excluded from completed-cycle sums and included as separate evidence. Missing history or dates produce unavailable values, and API failures, omissions, or safety limits are reported. JSON exports preserve filters, generated queries, exact state entries, and individual qualifying intervals.
